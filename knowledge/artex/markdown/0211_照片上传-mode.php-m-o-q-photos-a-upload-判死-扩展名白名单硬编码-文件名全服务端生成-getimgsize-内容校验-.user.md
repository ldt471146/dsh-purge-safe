## 描述

照片上传链判死。入口是 mode.php?m=o&q=photos&a=upload，但 target212.example.com:42 会把它转交 apps.php，真正执行的是 apps/photos/example.com（需登录 !$winduid && Showmsg('not_login')，且需 $db_phopen 开启）。上传类 lib/upload/target213.example.com:21-25 硬编码扩展名白名单 gif/jpg/jpeg/bmp/png（$this->ftype），lib/target52.example.com:31 用它做 `!isset($bhv->ftype[$ext])` 校验——.user.ini（ext=ini）与 .php/.pht/.php5 全部在这一步被拒。文件名由 getFilePath（target213.example.com:40-53）完全由服务端生成：{aid}_{randstr(4)}{timestamp}{md5(15)}.{ext}，用户唯一能影响的是扩展名，而扩展名被白名单锁死，所以前缀/路径一个字符都不可控。lib/target52.example.com:50-55 还对图片类型调 GetImgSize() 做内容校验，失败即 P_unlink 删除。落盘目录 attachment/photo/Mon_YYMM/ 在 DOCUMENT_ROOT 内、web 可访问，但产物始终是图片后缀，无解析依赖则无法执行。结论：照片上传这条链在 7.5 SP3 上不能 getshell，且比附件上传更严格（附件白名单来自后台 $db_uploadfiletype，照片是代码硬编码）。

## 用法

```
只有 3 包判定价值（确认功能是否开着、看上传是否报错），不建议投入更多：
1) GET /bbs/mode.php?m=o&q=photos（带 admin/123456 cookie）
   页面出现相册 UI 且无 photos_close → $db_phopen 开启。
2) GET /bbs/mode.php?m=o&q=photos&a=upload
   返回带 type=file 的表单 → 上传入口可达（管理员说的就是这个）。
3) POST 上传一个假扩展名文件（x.pht / x.php / x.ini 三种各试一次）到该表单
   预期：全部返回 upload_type_error（lib/target52.example.com:31）→ 白名单确认生效。
   若返回别的（例如提示"包含文件不存在"或 http 500），才值得继续看 —— 那说明 7.3.2 的 photoupload 类实现不同。
想要绕过只能指望 7.3.2 的 PhotoUpload::getFilePath 或 ftype 与 7.5 不同；用 1 个 POST 试 x.pht 即可判定，
不要再对 .user.ini 做任何尝试（文件名以 {aid}_ 开头且前缀不可控，即便白名单放开也拼不出点开头的文件名）。
```
