## 描述

判断"目标打不通"到底是**目标侧故障**还是**我方出口被封**，用多出口对照一次分清，避免整个团队在错误方向上白跑。
判据：
- **多出口全部失败**（经代理 502/超时 + 本机 --noproxy 连不上 + 自有 VPS 直连 000）且 **DNS 解析正常**、**代理访问第三方 200** ⇒ **目标侧故障/下线**（不要怀疑自己的出口，也不要换代理瞎试）。
- **仅单一出口失败、其它出口成功** ⇒ 是**该出口 IP 被封/被针对性拦截**（应换出口，而不是判定目标挂了）。
补充信号：
- 代理侧返回 **502 且耗时恰好落在代理超时阈值上**（如恒定 5.00s）⇒ 代理等上游超时，指向上游不可达，而非业务拒绝。
- 若**目标前置 CDN（Cloudflare 等）也返回 502** ⇒ CDN 回源失败，同样指向源站故障（若 CDN 返回 403/1020 才是按 IP/规则拦截）。
- 业务层错误码（如 JSON 里的 8005/8016/8011）说明**链路是通的**，与"不可达"要区分开，不要混为一谈。
排除法必做项：DNS 命中（nslookup 拿到真实 IP）→ 排除解析问题；代理自身访问一个公共站点（如 baidu.com）拿到 200 → 排除代理本身故障；直连目标真实 IP 与域名两条路都试 → 排除域名池/解析分流。
