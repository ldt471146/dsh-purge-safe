## 描述

结论：有管理员会话 + step_up_enabled=false 时插件 upload/enable 路由可调用，但签名为硬门禁（默认 allow_unsigned=false、trusted_publishers 为空，配置只在部署文件/环境变量，不在 DB、无 admin 接口可改）。不要在这条线上继续投入，除非拿到官方发布者私钥、部署配置写权限，或容器文件写入+DB 写入原语。

判据与请求：
1) 构造最小合法包（源码 backend/internal/service/plugin_manifest.go 约束）：schema_version=1；id 形如 acme.transport；requires.sub2api=">=0.2.0"、plugin_protocol=transport_api=ui_bridge=1（常量见 pkg/pluginapi/v1/runtime.go:12-16）；capabilities=[{id:"openai.oauth.outbound_transport.v1",platform:"openai",account_type:"oauth"}]；runtimes["linux-amd64"].path；ui.entrypoint="ui/index.html"；files 声明每个 zip 条目真实 sha256；不要多声明/少声明文件。
2) POST /api/v1/admin/plugins/upload（multipart 字段名 plugin，filename 后缀 .s2plugin）无 signature.json -> 400 {"message":"生产配置不允许安装未签名插件"}。
3) 带 signature.json {algorithm:"ed25519",key_id:X,signature:base64(64字节)}：key_id 不在 trusted_publishers -> 400「插件发布者密钥不受信任: X」；key_id=sub2api-openai-transport-v1 但 manifest.id≠local.sub2api.openai-transport -> 同样不受信任；两者都匹配合法但签名错 -> 400「插件签名校验失败」。
4) 源码：plugin_package.go verifySignature；config.go 默认 allow_unsigned=false、trusted_publishers={}；plugins 配置不在 DB，无设置接口写入。

复活条件/绕过思路（未验证）：enable/reconcile 路径不再验签，只在 Install/ensureLocalInstallation 缺本地文件时验签；若已有容器任意文件写，可在 plugins/installed/<id>/<ver>/ 放二进制并按 SHA256 造插件行（需 DB 写）后启用；或拿到官方发布者私钥直接签包。
