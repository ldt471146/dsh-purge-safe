## 描述

**全队必读的封禁维度情报**：本集群资金站（阿里云 WAF 前置，响应带 `Set-Cookie: acw_tc=...`）对敏感端点的封禁是「**方法 + 路径 + 来源 IP/信誉**」维度的**持续封禁**，**不是纯频率限流**。误判代价：被拦时返回的是 **HTTP 405 + HTML 拦截页**（不是 JSON、不是 429、不是 403），所以按"接口不存在/方法不支持"去解读会得出完全错误的结论（本例 loginV3 的 GET 本来就 405，容易被混淆）。

判据（可用于区分"被封"与"接口不存在/需鉴权"）：
· 被 WAF 拦：HTTP **405 Not Allowed**，`Content-Type: text/html`，body 2597 字节，含 `Sorry, your request has been blocked as it may cause potential threats to the server's security.` + `Your request ID is : ac...`，响应头带 `Set-Cookie: acw_tc=<hex>;path=/;HttpOnly;Max-Age=1800` 与 `cache-control: no-cache, no-store`，且**无应用层 JSON 信封**。
· 正常应用层拒绝：HTTP 200 + `{"status":403,"msg":"非法请求：缺少安全凭证","data":null}`（46 字节）。
· 接口不存在：HTTP 404 + `{"status":999,"msg":"Request Uri Not Found!","data":""}`（58 字节），或 nginx 原生 404 页（548 字节）。

触发与恢复特征（实测）：同一端点前几次 POST 可正常到达应用层，累计约 10 次 POST 后转入**持续封禁**；此后复测 4/4 次 POST 全被拦（其中 1 次直接 TLS `SSLEOFError: UNEXPECTED_EOF_WHILE_READING`），而**同一出口、同一时刻的 GET 请求仍 200 正常** → 证明封禁粒度锁定在「方法+路径+来源」，不会因等待而自动恢复，也不会影响其它路径/方法。

## 用法

```
**行动规则：**
1) 对该站 `loginV3` 等敏感路径发 POST 前先换出口（不同代理节点 / 不同 VPS）；**同一出口约 10 次 POST 即触发永久封禁**。
2) 见到 `HTTP 405 + 2597 字节 HTML + acw_tc cookie` 一律判为"被 WAF 拦"，**不要**判为"接口不存在/方法不对"；此时立即停手并换出口，不要原地重试（原地重试不会恢复，只会加深封禁）。
3) 被拦时用同出口发一次只读 GET 作为对照：GET 正常 = 确认是方法/路径级封禁，可直接据此写结论。
4) 复现脚本：`python ky588_waf2.py`（隔离对照实验，逐例打印 http/code/长度/WAF 判定，默认 6s 间隔）。
```

"""Diagnose whether the Aliyun WAF block is content-based or IP/reputation-based."""

def fire(tag, ep, body, hdr):
    s = requests.Session()
    s.proxies = K.PROXY
    ts = str(int(time.time() * 1000))
    h = {"User-Agent": K.UA, "Accept": "application/json, text/plain, */*", "Content-Type": "application/json"}

        t = r.text

        print("%-38s http=%s %s len=%-6s %s" % (tag, r.status_code, waf, len(t), t[:120].replace("\n", " ")))
    except Exception as e:
        print("%-38s ERR %s" % (tag, e))


# 1. plain GET read (control for IP reputation)
