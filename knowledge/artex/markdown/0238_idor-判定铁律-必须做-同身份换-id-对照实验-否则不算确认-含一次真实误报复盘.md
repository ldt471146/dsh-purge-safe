■ 误报内容
另一个智能体报告：`GET /bbs/example.com?id=1` → 200/1342B，无需任何 Cookie 即可读出 uid=1(admin) 的完整积分流水，判定为"未授权 IDOR，id 直连 uid，无归属校验"，并被排为最高优先目标。

■ 我的对照实验（14 发，两态）
· **无 Cookie（游客态）**：`example.com?id=1` → **560B**，正文是**只有表头的空表**（`ID | 时间 | 记录值 | 记录说明`），**零数据行**。
· **带 admin 登录态，换 ID 对照**：
| 请求 | 字节数 | 数据行数 | 日期串 |
|---|---|---|---|
| `id=1` | 1342B | 4 | 2026-10-06, 2026-10-05 |
| `id=2` | **1342B** | **4** | **完全相同** |
| `id=8916` | **1342B** | **4** | **完全相同** |
| `id=73` | **1342B** | **4** | **完全相同** |
| `id=`（空） | **1342B** | **4** | **完全相同** |
⇒ **五种 ID（含空值）响应字节数、行数、内容全部相同** → **`id` 参数被彻底忽略**，页面恒定输出"当前登录用户自己"的流水。无 Cookie 时因无用户上下文降为 560B 空表。

■ 误报成因
在**带 admin 登录态**的情况下请求 `id=1`，看到 admin 的流水，就判定为越权。**缺的正是"同身份换 ID"这一步对照**。

■ 连带否定
`id` 不进 SQL → 注入面不存在。注入判据序列已全部实测：`and 1=1` / `and 1=2` / 裸单引号 / 裸双引号 / 右括号 / `order by 99` / `id=-1` / `id=2` —— **9 发全部 560B、零报错、rows 恒为 0**（该站 `display_errors=On`，连一条 warning 都没有）→ **`INTO OUTFILE` 路径不通**。
同族的 `example.com` 的 `uid` 参数行为一致（`uid=2`/`uid=8916` 与 `uid=1` 响应恒等）→ **这一整套自建会员中心只认 session、不认 URL 参数**。

## 描述

IDOR/越权类结论必须做"同身份换 ID"对照实验才能确认。本条目记录一次真实误报：在带 admin 登录态下请求 example.com?id=1 看到 admin 自己的流水，被误判为"id 直连 uid、无鉴权 IDOR"并一度排到最高优先；实际做对照后发现 id 参数被完全忽略。

## 用法

```
判定 IDOR/越权的正确实验设计（三步缺一不可）：
1) **同身份换 ID**：保持同一 Cookie，把 ID 依次换成自己、他人（含不存在的值）、以及空值，比较**响应字节数 + 数据行数 + 数据内容**是否变化。若全部相同 → 参数被忽略，**不存在 IDOR**。
2) **换低权身份**：用另一个权限更低的账号（或未登录）访问同一 URL，看是否能读到高权数据。
3) **两态对照**：游客态与登录态各发一次，确认"数据出现"是因为"有 session"还是因为"URL 参数"。
反例警示：**"带管理员 Cookie 请求 id=1 看到了管理员的数据" 不构成 IDOR** —— 那是管理员看自己的数据；缺少第 1 步就无法区分。
```
