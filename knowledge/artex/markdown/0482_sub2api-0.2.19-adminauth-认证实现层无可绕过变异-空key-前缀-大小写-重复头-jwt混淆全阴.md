## 描述

用途：判定 sub2api 管理面鉴权层是否值得做认证实现变异（结论：不值得，除非拿到当前口令或当前 jwt_secret）。附带两个高复用要点：①不要把 libcurl/requests 自动归一化的 /./ 当作绕过；②重复 Authorization 会被前置层 400。

## 用法

```
1) 判据端点：GET /api/v1/admin/system/version、/api/v1/admin/users?page=1&page_size=1、/api/v1/admin/backups；三态：401 58B {"code":"UNAUTHORIZED"}（无认证）/ 401 62B {"code":"INVALID_ADMIN_KEY"}（x-api-key 分支被拒）/ 401 50B {"code":"INVALID_TOKEN"}（Bearer 解析/验签失败）/ 403 54B {"code":"FORBIDDEN","message":"Admin access required"}（有效 JWT 但 DB role≠admin）。
2) 已证否的变异（全部返 401，不要重复）：空 x-api-key、仅 adm_sc_ 前缀、前缀+空格、前导空格、4000 字符超长、Adm_Sc_/ADM_SC_ 大小写、tab/换行注入、重复 x-api-key 两序、Authorization: "Bearer "/"Bearer"、Bearer 填 scoped key/网关 sk- key、x-api-key 填网关 sk-/旧 scoped key、alg=none、空签名、缺 token_version、token_version=0 或字符串化、user_id 字符串、重复 sub/iss、WS Sec-WebSocket-Protocol: sub2api-admin, jwt.<token>。
3) 路径陷阱：必须用裸 /api/v1/admin/*。用 curl 打 /api/v1/./admin/* 或 %2e 会"看起来"到达应用（401），实际是 curl 把 . 段归一化后发出；raw socket 保留原路径时应用返回 Go 18B「404 page not found」（gin 不 normalize dot-segment，adminAuth 不执行）。验证方法：raw socket/HTTP 客户端保留原路径与 curl 对比。
4) 源码依据：middleware/admin_auth.go（x-api-key 优先、adm_sc_ 前缀分支、Bearer SplitN+TrimSpace）；service/auth_service.go ValidateToken（仅 HS256/384/512 + exp/nbf）；middleware/session_binding.go（bnd=="" 只跳过指纹校验，签名/查库/token_version/role 照旧）；service/custom_admin_keys.go AuthenticateScopedAdminKey（严格 4 段、id 24 位、secret 64 位）。
5) 复用建议：与其做实现层变异，不如投放资源到「取当前口令 / 取当前 jwt_secret / 未撤销 scoped key」三条线；若拿到任何有效签名密钥，注意 session binding 默认关闭（Hash=sha256(IP+"\n"+UA)[:16]），token 可从任意 IP/UA 重放。
```
