# 逆向工程（Reverse Engineering）

> 上游来源：<https://github.com/Hi-FullHouse/CyberSecurity-Skills> → `13-逆向工程-ReverseEngineering`
> 本技能包由上游 4 个 Markdown 文件转存，正文是导航与一句话要点，**中文原文完整保留在 `references/`**。

## 使用方式

1. 路线选择：**先静态（不运行）→ 再动态（受控运行）→ 恶意样本则先隔离**。
2. 目标产出通常是：算法/协议还原、加解密密钥、隐藏配置或 C2 地址、可按条件批量识别的特征（IoC/YARA）。
3. 分析结论要可复述：文件哈希、关键偏移、还原出的算法或密钥、验证方式。

## 知识清单（逐文件要点）

### 1. 静态逆向分析（Static Reverse Analysis）
- **一句话要点**：**不运行程序**，靠反汇编与反编译理解逻辑、发现漏洞、提取敏感信息。
- **覆盖**：文件格式分析（PE/ELF 结构、节区、导入导出表、资源）、加壳与混淆识别、反汇编与反编译工具链（IDA/Ghidra/objdump）、字符串与常量提取、算法与密钥定位、跨平台二进制差异分析、常用工具。
- **原文**：`references/StaticReverseAnalysis.md`

### 2. 动态调试分析（Dynamic Debug Analysis）
- **一句话要点**：**运行并调试**目标，实时观察执行流、内存状态与行为特征，验证静态分析的判断。
- **覆盖**：GDB 调试（断点、单步、内存与寄存器查看、脚本化调试）、x64dbg/WinDbg 与 IDA 动态调试、API 与系统调用跟踪、内存转储与脱壳、反调试与反虚拟机对抗思路、行为监控工具。
- **原文**：`references/DynamicDebugAnalysis.md`

### 3. 恶意软件分析（Malware Analysis）
- **一句话要点**：对样本做**全流程分析**——静态特征、行为、网络通信、IoC 提取与逆向，最终给出家族判断与检测建议。
- **覆盖**：安全分析环境搭建（隔离网络、快照、监控工具）、样本预处理与静态特征提取、行为分析（文件/注册表/进程/持久化动作）、网络通信与 C2 提取、内存取证与解包、IoC 提取与 YARA 规则思路、家族归类与报告撰写、常用工具。
- **原文**：`references/MalwareAnalysis.md`

### 4. 分类导读（README）
- **一句话要点**：上游该分类的官方目录说明（目标：对二进制与恶意样本逆向，理解原理、发现漏洞、提取逻辑）。
- **原文**：`references/README.md`

## 分析纪律

- **样本一律视为敌意代码**：在隔离虚拟机/沙箱里分析，禁止在办公宿主机直接运行未知样本。
- **不臆测、只记录**：结论要落到具体指令地址/偏移/字符串；说不清的写「待验证」。
- **可复现**：给出样本哈希、工具与版本、关键命令与参数，别人能按同样步骤复现你的结论。
- **产出可复用特征**：把 IOC、互斥体、C2 协议与 YARA 思路交给检测/响应侧，而不是只留一份分析笔记。
- **恶意样本相关操作仅在本地隔离环境进行**，不投递到互联网或第三方服务。
