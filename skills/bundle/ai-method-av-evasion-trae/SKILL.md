# 免杀流程化（Trae + Skills）

- 原文：https://www.ctfiot.com/304386.html 《AI免杀 – 利用Trae+Skills流程化免杀主流杀软》
- 核心观点：免杀不是一个"技巧"，而是**一条可被编排的流水线**；把它拆成 skill，让 AI IDE 循环执行，比人手搓稳定得多。

## 流水线拆解（我怎么落地）

```
① 基线       用 Defender/火绒/360/卡巴 各自跑一遍，记录"哪一层拦的"（静态特征/启发/行为/内存扫描）
② 特征定位   对 payload 做字节直方图 + 字符串扫描，找出被命中的常量（壳名、API 组合、节区名、PDB 路径）
③ 变形       PE 层（节区改名/加壳/入口混淆）→ 代码层（API 动态解析、字符串加密、控制流平坦化）
④ 加载器    分离 shellcode 与加载器；shellcode 用 RC4/AES + 分片，加载器只留最小 API 集
⑤ 逐个验证  每改一版跑一遍全杀软矩阵，记录"过了谁、死在谁手上、死在哪一层"
⑥ 回写     把"哪种变形让哪家从行为层掉到静态层"记成规则，下一版直接复用
```

## 把它做成 skill 的关键

- 每一步的**输入输出必须是文件**（payload、报告 json、日志），AI 才知道自己改了什么；
- 每一步都要**可回滚**（保留原始样本与 diff），否则连"哪次改动有效"都说不清；
- 验证矩阵要**自动跑 + 自动记录**，人只做决策不做搬运。

## 我在本项目里怎么用（合规口径）

只做两件事：
1. **对抗性验证**：给授权客户测 EDR 检出率，产出「当前版本在 X 家产品上的检出/绕过情况」；
2. **检测规则反向输出**：把"绕过手法"翻译成 YARA / Sigma / EDR 自定义规则，交给蓝队——
   这也是 `cszh-performing-malware-triage-with-yara` 与 `secdetection` 类技能的输入。

## 风险与边界

- 变形后的样本**一律隔离环境**跑，绝不落地到宿主机；
- 杀软矩阵要覆盖「静态 / 启发 / 行为 / 内存」四层，只看 VirusTotal 数字会自欺欺人；
- 每次验证都要留存 hash 与时间戳，报告里要能复现。
