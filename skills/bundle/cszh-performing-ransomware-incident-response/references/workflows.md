# 勒索软件（Ransomware）事件响应（Incident Response）- 详细工作流程

## 阶段 1：检测与初步评估（0-30 分钟）

### 检测来源
1. EDR/AV 发出勒索软件行为告警（大量文件加密）
2. 用户报告文件无法访问或出现勒索说明
3. SIEM 关联可疑模式（VSS 删除 + 大量文件写入）
4. 备份系统告警（备份失败或损坏）
5. 诱饵文件（Canary file）监控触发

### 初步评估步骤
1. 确认勒索软件活动（排除误报或合法加密）
2. 识别零号患者（patient zero，最初受感染的系统）
3. 根据勒索说明或加密文件扩展名确定勒索软件变种
4. 检查加密是否仍在进行或已完成
5. 评估范围：单台主机、部门级还是全企业
6. 激活事件响应团队，建立作战指挥室（war room）

### 变种识别
1. 将勒索说明上传至 ID Ransomware（id-ransomware.malwarehunterteam.com）
2. 提交加密文件样本以识别加密算法
3. 对照已知勒索软件数据库检查文件扩展名
4. 与威胁情报（Threat Intelligence）源交叉比对 IOC
5. 在威胁情报数据库中搜索比特币钱包地址

## 阶段 2：遏制（Containment）（30-120 分钟）

### 立即行动
1. 通过 EDR 对所有已确认感染主机进行网络隔离
2. 在边界防火墙（perimeter firewall）封锁已知 C2 IP/域名
3. 禁用网段间文件共享（SMB、NFS）
4. 封锁横向移动（Lateral Movement）协议（RDP、WinRM、PsExec）
5. 禁用已泄露的用户/服务账户
6. 将备份系统下线（防止被加密）

### 网络分段（Network Segmentation）
1. 在 VLAN 间实施紧急防火墙规则
2. 对受影响网段禁用 VLAN 间路由
3. 封锁非必要端口的东西向流量
4. 在受影响网段启用全量数据包捕获
5. 部署网络蜜标（honey token）

### 备份保护优先级
1. 断开备份网络与生产环境的连接
2. 验证不可变备份副本是否存在且完好
3. 测试样本恢复以确认备份可用性
4. 记录每个系统的最后已知良好备份日期
5. 如使用云备份，验证对象锁定/WORM 设置

## 阶段 3：调查（2-48 小时）

### 确定初始访问向量
1. 审查 VPN/远程访问日志以发现泄露凭据
2. 检查邮件日志中的钓鱼（Phishing）投递记录
3. 分析公开应用程序遭受的漏洞利用情况
4. 审查事件日志中的 RDP 暴力破解（Brute Force）尝试
5. 检查供应链/第三方访问日志

### 绘制攻击时间线
1. 关联 SIEM/EDR 数据以构建攻击年表
2. 识别驻留时间（Dwell Time）（初始访问到加密的时间）
3. 绘制攻击者在网络中的横向移动路径
4. 识别攻击者访问过的所有系统
5. 确定加密前是否发生了数据外泄（Exfiltration）

### 证据收集
1. 从关键系统捕获内存镜像
2. 在整改前创建取证磁盘镜像
3. 导出相关 SIEM 日志（身份验证、文件访问、网络）
4. 保留 EDR 检测数据和时间线
5. 记录所有勒索沟通内容

## 阶段 4：根除（Eradication）（24-72 小时）

### 清除攻击者持久化（Persistence）机制
1. 识别并清除所有后门（Web Shell、RAT、植入程序）
2. 删除攻击者创建的计划任务
3. 清除恶意注册表条目
4. 删除未经授权的用户账户
5. 撤销所有泄露凭据（必要时包括 KRBTGT）
6. 修补用于初始访问的漏洞

### 验证清洁状态
1. 对所有系统运行完整的 AV/EDR 扫描
2. 使用针对该勒索软件家族的 YARA 规则进行扫描
3. 验证无未授权进程或服务
4. 检查无文件持久化（Fileless Persistence）机制
5. 验证组策略对象（Group Policy Object）未被篡改

## 阶段 5：恢复（Recovery）（24 小时 - 2 周）

### 恢复优先级
| 优先级 | 系统类别 | 恢复目标 |
|--------|---------|---------|
| P1 | 域控制器、DNS、DHCP | 4-8 小时 |
| P2 | 邮件、通信系统 | 8-24 小时 |
| P3 | 核心业务应用程序 | 24-72 小时 |
| P4 | 文件共享、次要系统 | 3-7 天 |
| P5 | 非关键工作站 | 1-2 周 |

### 恢复步骤
1. 从已知良好镜像重建系统（非受感染备份）
2. 从已验证的干净备份恢复数据
3. 重新接入网络前应用所有安全补丁
4. 全企业范围内重置所有密码
5. 在所有远程访问上实施 MFA
6. 分阶段重新接入系统，并加强监控
7. 恢复后验证数据完整性

### 解密评估
1. 在 nomoreransom.org 查找可用解密工具
2. 联系执法机构获取可能缴获的解密密钥
3. 评估是否可能进行部分解密
4. 评估第三方解密服务（需谨慎）
5. 记录无法恢复的数据

## 阶段 6：事后处理（1-4 周）

### 经验教训（Lessons Learned）
1. 开展正式的事后审查（After-Action Review）
2. 记录完整攻击时间线
3. 识别响应过程中的成功与不足
4. 根据调查结果更新事件响应手册（Playbook）
5. 向高管领导层和董事会汇报

### 预防性改进
1. 实施或强化不可变备份
2. 部署额外的网络分段
3. 改进终端检测规则
4. 开展安全意识培训
5. 定期测试备份恢复流程
6. 实施特权访问管理（Privileged Access Management，PAM）
